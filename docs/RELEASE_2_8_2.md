# 2.8.2 发布说明

日期：2026-11-14（北京时间）。本版针对三个真实体验问题：摸鱼会话的提示词缓存命中率过低导致费用偏高、动态产出不稳定且没有视频卡片、私信被排在刷视频后面。另修「本轮 token」恒为 0 的账本冻结，并给鱼模式加了「只做B站」边界。本文件不代替外部发布回执。

## 缓存命中率（费用）

真机同一台宿主上，普通会话提示词缓存命中 97.3%，摸鱼会话只有 14%–36%（266 次请求里 164 次缓存为 0）。根因是 `systemPrompt.section` 里塞了**每次请求都会变**的内容：分钟级时钟、`【这次刷到哪里】` 浏览进度 JSON、实时配额计数、动态开头镜子和按轮次轮换的学习注入；这段落在 14k 字提示词的 1400 字处，改一个数字后面 12.7k 字全部作废。

现在：时钟降为**时段粒度**（凌晨/清早/上午/…＋星期）、进度和分钟级时间移到**工具回执**的 `browse_progress` / `live` 快照（尾部追加，不改前缀）、学习轮换按天、系统提示词只留稳定简报。新增字节级回归 `tests/prompt-cache-stability.test.mjs`（工具调用前后系统提示词逐字节一致）。修复后的命中率以实际运行为准，本文件不给具体提升数字。

## 动态：稳定产出与视频卡片

- 目标/章程恢复肯定式触发：有真实想说的就 `bili_moment`，看乐了、想吐槽、想安利都算；配额措辞改为"还有多少余量"。
- 节奏按**上一条动态的发送时间**算：距上一条满约半小时（30 分钟 + 最多 5 分钟抖动）就能发，小时上限 3，且不吃节奏系数（"轻快 0.5" 不会把它压到 15 分钟）。
- `bili_moment` 新增 `bvid` 参数：正文出现 BV 号也会自动识别；链接**单独一行**追加在正文末尾，B站渲染成带标题的视频卡片；链接计入 300 字上限，正文已有链接不重复。
- `lastMomentAt` 只在确认发出后写：预占名额和失败退回不再重置"距上一条半小时"的节奏。
- 成功回执补 `success:true` 并写活动流水，能和查询区分开。

## 私信优先级

目标与章程把私信提到**每轮开场第一件事**；浏览进度在距上次成功查收件箱超过 20 分钟时优先建议 `check-dm`。收件箱结果加 45 秒本地去重（查得太勤会被平台限流）；只有**成功读到**才记"上次查过"，失败至少隔 10 分钟再试。

两个真 bug：① `bili_dm_reply` 复核时把收件箱**失败**（-509/登录态）当成"消息已消失"误报 `staleSeqno` —— 现在先判错误，如实说"没取到，稍后重试"；② 复核写 `num:100` 但 MCP 侧硬钳到 50 —— 改成 50 并注明。

## 只做B站（2026-11-14 真机事故）

连续 22 条视频读不到字幕后，鱼开始翻日志、查 sqlite、在工作区写诊断脚本。现在：目标与章程新增「只做B站」——鱼模式不改工作区文件、不写脚本、不跑命令排查、不读插件源码；异常最多用 `bili_status` / `bili_records` 看一眼或如实说一句，然后换来源继续刷。浏览进度新增 `noSubtitleStreak`，连续 5 条无字幕把下一步强制改成"换来源"，提示里明说别写脚本查原因。

## 活跃度四项（使用者要求）

刷过的片**尽量留一句评论**（连读 2 条没说话会把欠账摆进下一步提示）；评论/动态**多配表情**；动态评论与评论回复**有就回**；动态**约每半小时一条**（见上）。授权、判重、节奏与风控退避照旧。

## 本轮 token 显示修复

真机实录：一整趟烧了 35.5M token，面板「本轮 token」一直是 0，账本开局 5 秒被记成 `goal-disarmed / 0 tok`。根因：durable goal 视图刻意不含 `activation`，折叠出的 activation 在开局几秒可能是瞬时 "disarmed"，idle 事件据此把用量段提前结算并永久冻结。现在 idle 结算**只认 phase**；已冻结但 goal 仍在 active 的段在状态口自愈重开（冻结时账 0 保留原基线重算，账大于 0 折进 offset 重立基线，都不重复记账）。今日/累计也因此恢复完整计量。
